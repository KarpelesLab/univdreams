# Source language: `.ud`

The `.ud` ("universal dreams") source language is a C-like surface syntax with first-class **directives** that pin compiler choices. The directives are what makes the language capable of being a complete, executable specification of a binary.

This document is a sketch of v0. It will tighten as the parser is implemented.

## Design principles

1. **Familiar where it can be.** Functions, types, expressions, and statements look like C/C++. A reader who knows C should be able to skim a `.ud` file and understand control flow at first glance.
2. **Explicit where it must be.** Every choice that affects the emitted bytes is either pinned by a directive or determined by a deterministic rule. There is no implicit "the compiler will figure it out" — at least not silently.
3. **Round-trip first.** The pretty-printer is deterministic. The grammar is unambiguous. `parse(emit(ast))` is the identity on ASTs, and `emit(parse(text))` is the identity on canonical text.
4. **Escape hatches are first-class.** `@asm`, `@raw`, and `@encoding(opaque=…)` are part of the language, not workarounds. A `.ud` file is *always* a complete representation of its binary, even when the lifter could not produce structured source.

## File-level header

Every `.ud` file begins with a module header that pins target context:

```ud
@module {
    arch:   "x86_64",
    abi:    "sysv",
    format: "elf",
    os:     "linux",
    bits:   64,
    endian: "little",
    link: {
        base:    0x400000,
        page:    0x1000,
        rwx:     false,
    },
    build: {
        // Non-deterministic header bits captured verbatim from the input,
        // re-emitted on compile so the file ends up byte-identical.
        elf_ident:  [0x7F,0x45,0x4C,0x46, 0x02,0x01,0x01, 0x00,0x00,0x00,0x00,0x00,0x00,0x00,0x00,0x00],
        e_flags:    0x0,
        sht_order:  ["", ".interp", ".note.gnu.property", ".note.gnu.build-id", … ],
        build_id:   "f3a02e1b…",
    },
}
```

The `build` block is generated by the decompiler from observed bytes and is normally not edited. It captures the things that are *correct* values for the input but couldn't be derived by recompiling.

## Sections

```ud
@section(".rodata", flags=["alloc"], align=8) {
    @symbol("hello") @addr(0x402004)
    let hello: [u8; 14] = b"Hello, world!\n";
}
```

A `@section` block scopes everything inside it to a particular ELF/PE/Mach-O section. Entries inside are emitted in the order written; the section's bytes are the concatenation, plus any `@pad` directives.

## Functions

```ud
@addr(0x401050)
@align(16)
@prologue("std")           // standard sysv-x64 prologue: push rbp; mov rbp, rsp
fn sub_401050(buf: ptr<u8> @rdi, len: usize @rsi) -> i32 @rax {
    @reg(rbx) let i: usize = 0;
    @reg(rax) let acc: u32 = 0;

    while i < len {
        acc = acc.wrapping_add(buf[i] as u32);
        i += 1;
    }

    return acc as i32;
}
```

What's pinned here:
- **Function address**: `@addr(0x401050)` — used as the link-order key.
- **Alignment** of the function start: `@align(16)`.
- **Prologue style**: `@prologue("std")`. Other values: `"none"` (no frame), `"omit-fp"` (push only callee-saves), `"custom"` (followed by an inline asm block defining the bytes).
- **Parameter registers**: `@rdi`, `@rsi`. With `@abi("sysv")` set in the module header, these are usually implied; the decompiler still writes them explicitly so the file is self-contained.
- **Return register**: `@rax`.
- **Local register pinning**: `@reg(rbx)`, `@reg(rax)`. The compiler must use these registers for these locals.

A function's default name is `sub_<hex_addr>`. Renaming is a pure source-level edit; the `@addr` keeps the link-order stable.

## Directive vocabulary (v0)

Module-scoped:

| Directive | Effect |
|-----------|--------|
| `@module { … }` | Required at the top of every file. |
| `@section(name, …) { … }` | Scopes inner items to a specific section. |
| `@import("strlen", from="libc.so.6") -> ptr` | Declares an external symbol. |

Item-scoped:

| Directive | Effect |
|-----------|--------|
| `@addr(0x…)` | Pin the address; default link-order key. |
| `@align(N)` | Alignment of the item start. |
| `@pad(N, fill=0xCC)` | Pad with `N` bytes of `fill` after this item. |
| `@symbol("name")` | Emit a symbol-table entry pointing here. |
| `@signature("strlen")` | Mark this function as recognized stdlib (used by signature matcher). |

Function-scoped:

| Directive | Effect |
|-----------|--------|
| `@abi("sysv" \| "ms64" \| "aapcs" \| "custom")` | Calling convention. |
| `@prologue("std" \| "none" \| "omit-fp" \| "custom")` | Prologue/epilogue shape. |
| `@stack(size=N, align=A)` | Pin frame layout. |
| `@spill(slot=N, var=…)` | Pin a specific spill slot. |
| `@tail` | Mark the call as a tail call (jmp instead of call). |

Statement / expression-scoped:

| Directive | Effect |
|-----------|--------|
| `@reg(rN)` | Pin a local to a register. |
| `@no_reorder { … }` | Forbid reordering across this block. |
| `@loop(kind, encoding=…) while/for/do … { … }` | Pin loop lowering shape. |
| `@switch(table_at=0x…, default=…) switch (…) { … }` | Pin switch-table layout. |
| `@branch(encoding="short" \| "near" \| "far")` | Pin branch encoding size. |
| `@encoding(prefix=…, rex=…, …)` | Pin per-instruction encoding bits. |

Escape hatches:

| Directive | Effect |
|-----------|--------|
| `@asm("mov rax, rbx; …")` | Emit literal assembly text; assembler handles encoding. |
| `@raw(at=0x…, bytes=[…])` | Emit raw bytes at an address; opaque to analysis. |
| `@encoding(opaque=[0x48, 0x89, 0xC8])` | Force these exact bytes for an op. |

## Worked example: round-trip preservation

Suppose the input contains:

```
401050:  48 89 f0          mov  rax, rsi          ; redundant move kept by compiler
401053:  48 31 c9          xor  rcx, rcx
401056:  48 39 d1          cmp  rcx, rdx
401059:  74 0d             je   short 0x401068
40105b:  ...
```

Decompiled:

```ud
@addr(0x401050)
@prologue("none")
fn sub_401050(arg0: u64 @rdi, arg1: u64 @rsi, arg2: u64 @rdx) -> u64 @rax {
    @encoding(rex_w=1)
    @reg(rax) let result: u64 = arg1;     // mov rax, rsi

    @reg(rcx) let i: u64 = 0;             // xor rcx, rcx — emitted as xor not mov

    @branch(encoding="short")
    if i == arg2 {
        return result;
    }
    // ...
}
```

What's preserved:
- The redundant `mov rax, rsi` is encoded by the local-with-`@reg(rax)` initialization plus the `@encoding(rex_w=1)`.
- The `xor`-zeroing idiom for `rcx` is the canonical lowering of `let _: u64 = 0` *with `@reg(rcx)`*; the encoder picks `xor reg,reg` over `mov reg,0` because it's shorter and that's the deterministic default. If the original had used `mov`, the directive would say `@encoding(strategy="mov_imm")` instead.
- The short-jump encoding on the `je` is preserved by `@branch(encoding="short")`.

## What it doesn't try to do

- **No type inference contract.** Types in `.ud` are concrete and pinned. The decompiler infers types and writes them; it does not promise to find the same types as the original source — only types that, when compiled, produce the same bytes.
- **No semantic refactoring on emit.** The pretty-printer never reorders statements, never renames variables, never simplifies `x = x + 1` to `x++`.
- **No imports of headers or modules other than via `@import`.** Linking is explicit.

## Reserved syntax

The `@` sigil is reserved for directives. Identifiers may not begin with `@`. Comments are `//` and `/* */` as in C. String literals support standard C escapes plus `\xNN` and `\uNNNN`. Byte-string literals are `b"…"`. Numeric literals: decimal, `0x` hex, `0b` binary, `0o` octal; `_` separators allowed.
